# 13. 综合项目路线

前面章节已经覆盖概念、核心能力、架构和工程。本章把知识变成项目。项目要从小到大，不要第一个项目就做“全能 Agent 平台”。

本章目标：通过 5 个项目完成从入门到精通的能力闭环。
下一章：术语表，方便回查概念。

## 项目 1：结构化信息抽取器

目标：输入一段文本，输出固定 JSON。

能力点：

- LLM 基础调用。
- 指令设计。
- 结构化输出。
- 基础评测。

验收：

- 至少 20 条样例。
- JSON schema 校验。
- 错误输入能返回明确失败原因。

为什么先做它：这是 Agent 的 L0-L1 基础。如果结构化输出都不稳定，后面工具调用会更不稳。

## 项目 2：最小工具调用 Agent

目标：Agent 根据问题选择计算器、时间查询或本地知识查询工具。

能力点：

- 工具 schema。
- 工具参数校验。
- Agent loop。
- 最大轮数和错误恢复。

验收：

- 工具调用路径可打印。
- 参数错误能重试或询问用户。
- 不需要工具的问题直接回答。

可参考 `examples/minimal-agent`。

## 项目 3：内部知识库 RAG Agent

目标：基于一组公司制度文档回答问题，并给出引用。

能力点：

- 文档切分。
- metadata。
- 检索与重排。
- 引用生成。
- 提示注入防护。

验收：

- 回答必须带文档引用。
- 资料不存在时不能编造。
- 用户无权限时不能泄露。
- 至少 30 条 RAG 评测样例。

## 项目 4：售后处理工作流 Agent

目标：根据用户诉求、订单状态和售后政策，给出处理建议，并在必要时创建退款草稿。

能力点：

- 工作流与 Agent 混合。
- 数据工具和动作工具区分。
- 人工审批。
- 审计日志。
- 轨迹评测。

验收：

- 未查订单前不能退款。
- 真实退款必须审批。
- 缺信息时先询问。
- 每次工具调用有 trace。

## 项目 5：多 Agent 研究报告系统

目标：多个 Agent 协作完成一份带引用的研究报告。

建议角色：

- Planner：拆解研究问题。
- Researcher：检索和筛选资料。
- Analyst：提取观点和证据。
- Writer：生成报告。
- Reviewer：检查引用、逻辑和遗漏。

能力点：

- 多 Agent 职责隔离。
- 结构化交接。
- 并行和汇总。
- evaluator-optimizer。
- 成本和轮数控制。

验收：

- 每个 Agent 有清晰输入输出 schema。
- 最终报告区分事实、推断、建议。
- Reviewer 能指出至少 3 类问题。
- 有端到端 trace。
- 有回归评测集。

## 精通级毕业项目

选择一个真实业务场景，完成完整工程包：

```text
docs/
  product-requirements.md
  architecture.md
  threat-model.md
  eval-plan.md
  runbook.md
evals/
  cases.yaml
src/
  agent runtime
  tool gateway
  tools
  rag pipeline
tests/
  unit tests
  eval regression tests
```

毕业标准：

- 能解释为什么需要 Agent。
- 能证明比简单方案更好。
- 有明确权限边界。
- 有离线评测和线上观测计划。
- 有失败恢复和人工介入。
- 有成本预算。
- 能被另一个工程师接手维护。

## 项目展示建议

GitHub README 应包含：

- 问题背景。
- 架构图。
- Agent loop 或 workflow 图。
- 工具清单。
- 安全策略。
- 评测结果。
- 已知限制。
- 运行方式。

做到这里，你已经不是“会调 Agent 框架”，而是能对 Agent 系统质量负责。
