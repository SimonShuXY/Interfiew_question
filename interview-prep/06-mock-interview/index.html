模拟面试¶

模拟面试的目标是暴露卡点。不要只在脑子里觉得自己会，要录音或计时口述。

60 分钟模拟面试结构¶

时间 环节 内容
0-5 分钟 自我介绍 重点讲 Agent 项目和工程能力
5-20 分钟 基础题 Agent、RAG、工具、MCP、记忆、eval
20-40 分钟 系统设计 智能客服、代码 Agent、知识库或数据 Agent
40-52 分钟 项目深挖 架构、指标、失败案例、权衡、安全
52-58 分钟 反问 问团队的 Agent 场景、eval、工具生态和上线难点
58-60 分钟 复盘 记录答得不清楚的地方

评分表¶

维度 0 分 1 分 2 分 3 分
概念清晰 混淆概念 能定义 能对比 能结合场景和边界
工程落地 只讲模型 有模块 有流程 有权限、eval、trace、成本
系统设计 零散 有主链路 模块完整 有权衡、失败恢复和指标
项目表达 像 demo 能运行 有评测 有指标、失败复盘和改进
沟通结构 跳跃 基本清楚 有层次 能主动澄清和总结

目标：正式面试前总分稳定在 12 分以上，强面试目标是 14 分以上。

基础题快问快答¶

每题控制在 90 秒内：

  • Agent 和 workflow 的区别是什么？
  • 为什么 Agent 需要终止条件？
  • 工具 schema 怎么设计？
  • MCP 解决什么问题？
  • RAG 幻觉来自哪里？
  • 短期记忆和长期记忆怎么分？
  • Harness 是什么？
  • 为什么只看 final answer eval 不够？
  • 如何防 prompt injection？
  • 如何降低 Agent 成本和延迟？

系统设计抽题¶

每题控制在 20 分钟内：

  • 设计智能客服 Agent。
  • 设计代码修复 Agent。
  • 设计企业知识库 Agent。
  • 设计数据分析 Agent。
  • 设计浏览器操作 Agent。
  • 设计 Agent eval harness。

回答时必须覆盖：

  • 需求和边界。
  • 主架构。
  • 工具和数据。
  • 状态和记忆。
  • 安全和权限。
  • eval 和 trace。
  • 生产指标。

项目深挖问题¶

准备好回答：

  • 为什么这个任务需要 Agent？
  • 你最难的工程问题是什么？
  • 你怎么知道 Agent 变好了？
  • 失败最多的 case 是什么？
  • 你如何定位失败原因？
  • 哪些动作需要人工确认？
  • 如果成本翻倍，你怎么优化？
  • 如果模型版本升级导致行为变差，你怎么回滚？
  • 如果用户上传恶意文档，你怎么防？
  • 如果让你再做一版，你会改哪里？

反问问题¶

可以选择 2 到 3 个：

  • 团队目前 Agent 最核心的落地场景是什么？
  • 你们如何做 Agent eval 和线上质量监控？
  • Agent 可以调用哪些内部工具？权限边界怎么设计？
  • 当前最大的瓶颈是模型能力、数据质量、工具集成还是产品信任？
  • 团队更偏 framework 层、应用层，还是 eval/observability 层？
