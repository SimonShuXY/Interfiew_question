# 92 道 Agent 面试题

使用方式：

- 第一轮：只看题目，口述 2 到 3 分钟。
- 第二轮：对照“回答抓手”，补齐定义、边界、机制、风险和指标。
- 第三轮：给每题准备一个真实例子，最好来自自己的项目。

## Agent 基础

| 编号 | 面试题 | 回答抓手 |
| --- | --- | --- |
| Q001 | 你如何定义 Agent？它和普通 LLM 应用有什么区别？ | Agent 有目标、状态、工具、循环和终止条件；普通 LLM 应用多是单轮或固定流程。 |
| Q002 | Agent、chatbot、workflow、RAG 分别是什么关系？ | chatbot 偏交互界面，workflow 偏确定流程，RAG 偏知识增强，Agent 偏动态决策和行动。 |
| Q003 | 一个 Agent 系统通常由哪些核心组件组成？ | 模型、指令、工具、状态、记忆、规划器、执行器、评测、日志、权限。 |
| Q004 | 什么场景适合 Agent，什么场景不适合？ | 适合多步、开放、需要工具反馈的任务；不适合强确定、低延迟、高风险且规则清晰的任务。 |
| Q005 | 为什么很多“Agent demo”不能直接生产化？ | 缺 eval、trace、权限、失败恢复、成本控制、上下文管理和安全边界。 |
| Q006 | Agent 的能力边界应该如何定义？ | 明确能做什么、不能做什么、需要确认什么、工具能访问什么、何时停止。 |
| Q007 | Agent 的自主性越高越好吗？ | 不一定；自主性要和风险、可验证性、用户信任、成本和权限匹配。 |
| Q008 | 面试中如何判断一个系统该用 Agent 还是 workflow？ | 如果路径稳定且规则清晰，用 workflow；如果路径动态、需要探索和工具反馈，考虑 Agent。 |

## LLM 与 Prompt 基础

| 编号 | 面试题 | 回答抓手 |
| --- | --- | --- |
| Q009 | Token 是什么？为什么 Agent 设计必须关注 token？ | token 决定上下文容量、成本、延迟和可保留信息量。 |
| Q010 | temperature、top_p、max tokens 分别影响什么？ | temperature/top_p 影响采样随机性；max tokens 控制输出长度和截断风险。 |
| Q011 | 为什么生产 Agent 通常需要结构化输出？ | 便于程序解析、校验、重试、审计和评测。 |
| Q012 | JSON schema 输出失败时如何处理？ | schema validation、自动修复、重新生成、降级到人工或安全默认值。 |
| Q013 | System prompt、developer prompt、user prompt 的职责如何划分？ | 系统和开发者定义角色、边界、工具策略；用户给任务和上下文。 |
| Q014 | Few-shot 在 Agent 中有什么作用？ | 稳定格式、展示工具选择模式、约束推理风格，但会占上下文。 |
| Q015 | Prompt cache 的收益和局限是什么？ | 重复前缀可降低成本和延迟；动态上下文、个性化内容和频繁变动会降低命中率。 |
| Q016 | 如何避免 prompt 越写越长？ | 抽象策略、使用结构化 state、检索相关上下文、压缩历史、把规则下沉到代码。 |
| Q017 | 为什么只靠 prompt 很难保证 Agent 安全？ | 模型是概率系统，工具权限、校验、审批、沙箱和审计必须由系统层兜底。 |
| Q018 | 如何设计一个可维护的 Agent prompt？ | 分层组织：目标、边界、工具策略、输出格式、失败处理、例子和禁止行为。 |

## 规划与执行

| 编号 | 面试题 | 回答抓手 |
| --- | --- | --- |
| Q019 | 什么是 Agent loop？ | 循环进行观察、推理、行动、接收工具结果，直到完成或触发停止条件。 |
| Q020 | ReAct 的核心思想是什么？ | 推理和行动交替，模型根据观察动态选择下一步。 |
| Q021 | Plan-and-Execute 和 ReAct 的区别是什么？ | 前者先规划再执行，适合长任务；后者边看反馈边行动，适合不确定环境。 |
| Q022 | Reflection 在 Agent 中解决什么问题？ | 复盘失败、更新策略、改善下一次尝试；需要防止自我确认和成本膨胀。 |
| Q023 | 如何设计 Agent 的终止条件？ | 目标完成、最大步数、超时、无进展检测、重复动作检测、风险触发。 |
| Q024 | Agent 跑偏通常有哪些原因？ | 目标不清、工具描述误导、上下文污染、缺少状态、缺少 eval、停止条件弱。 |
| Q025 | 如何避免 Agent 死循环？ | 步数预算、状态去重、工具调用去重、progress evaluator、强制总结和人工介入。 |
| Q026 | 状态机和 LLM planner 如何结合？ | 状态机管硬约束和阶段迁移，LLM 处理开放决策和文本理解。 |
| Q027 | 什么时候应该让模型重新规划？ | 工具失败、环境变化、计划步骤不可执行、用户目标变化、成本超预算。 |
| Q028 | 如何评估一个规划器好不好？ | 计划可执行性、步骤冗余率、工具选择正确率、完成率、平均步数和失败恢复率。 |

## 工具、MCP 与 Skills

| 编号 | 面试题 | 回答抓手 |
| --- | --- | --- |
| Q029 | Function calling 的本质是什么？ | 模型选择函数和参数，实际执行由代码完成。 |
| Q030 | 一个好的工具 schema 应该包含什么？ | 清晰名称、用途边界、参数类型、必填字段、枚举、约束、错误语义。 |
| Q031 | 为什么工具描述不能写得过于宽泛？ | 模型会误用工具；宽泛描述会导致权限扩大、参数错误和不可评测。 |
| Q032 | 读工具和写工具的设计有什么区别？ | 写工具风险更高，需要权限、dry-run、审批、幂等、回滚和审计。 |
| Q033 | 工具调用失败时应该如何恢复？ | 分类错误、重试、修正参数、换工具、请求用户补信息、停止并解释。 |
| Q034 | MCP 解决什么问题？ | 用标准协议连接 LLM 应用和外部工具、资源、提示模板，降低集成碎片化。 |
| Q035 | MCP 中 Host、Client、Server 分别是什么？ | Host 是 LLM 应用，Client 是连接器，Server 暴露工具、资源和 prompts。 |
| Q036 | MCP 和普通 function calling 有什么区别？ | function calling 是模型调用函数的接口模式；MCP 是外部能力发现和通信协议。 |
| Q037 | Skill 和 tool 的区别是什么？ | tool 是可执行能力；skill 更像可渐进加载的任务说明、流程知识和能力包。 |
| Q038 | 如何防止 Agent 通过工具做危险动作？ | 最小权限、参数校验、审批、沙箱、策略引擎、审计日志、危险动作默认阻断。 |

## RAG 与知识库

| 编号 | 面试题 | 回答抓手 |
| --- | --- | --- |
| Q039 | RAG 解决什么问题？不能解决什么问题？ | 解决外部知识和可引用问题；不能自动保证推理正确、权限正确或资料真实。 |
| Q040 | Embedding 的作用是什么？ | 把文本或多模态内容映射到向量空间，用相似度做语义召回。 |
| Q041 | Chunk 大小如何选择？ | 平衡语义完整性、召回精度、上下文成本；文档结构和任务类型决定策略。 |
| Q042 | 固定 chunk 和语义 chunk 各有什么优缺点？ | 固定简单稳定；语义更贴合内容但依赖解析质量和成本。 |
| Q043 | 混合检索为什么常比纯向量检索好？ | BM25 擅长关键词和专有名词，向量擅长语义，组合能提升召回覆盖。 |
| Q044 | Rerank 放在检索链路哪个位置？ | 初召回后、送入 LLM 前，用更强模型重排候选片段。 |
| Q045 | Query rewrite 在 RAG 中有什么作用？ | 补全多轮上下文、改写歧义问题、生成多查询、加入过滤条件。 |
| Q046 | 如何处理“知识库没有答案”的问题？ | 检索置信度阈值、引用要求、拒答策略、请求补充、人工升级。 |
| Q047 | RAG 幻觉有哪些来源？ | 召回错、上下文不完整、模型过度推断、引用错配、过期文档、权限混入。 |
| Q048 | 如何评测 RAG 系统？ | 检索召回、上下文相关性、答案正确性、引用准确率、拒答正确率、延迟和成本。 |

## 记忆与上下文工程

| 编号 | 面试题 | 回答抓手 |
| --- | --- | --- |
| Q049 | 短期记忆和长期记忆有什么区别？ | 短期服务当前会话和任务状态；长期保存跨会话事实、偏好和历史经验。 |
| Q050 | Session State 应该存什么？ | 用户目标、任务阶段、已确认信息、工具结果摘要、审批状态、未解决问题。 |
| Q051 | 长期记忆写入应该满足什么条件？ | 用户同意、事实稳定、可溯源、可删除、避免敏感信息滥存。 |
| Q052 | 什么是上下文污染？ | 不相关、过期、恶意或低质量信息进入上下文，影响模型判断。 |
| Q053 | 上下文压缩有哪些方法？ | 摘要、结构化 state、检索式记忆、窗口滑动、重要性打分、任务分段。 |
| Q054 | 为什么“把所有历史都塞进 prompt”不是好方案？ | 成本高、延迟高、噪声多、易污染、超过上下文窗口且难以审计。 |
| Q055 | 如何设计 Agent 的工作记忆？ | 明确字段、更新规则、来源、置信度、过期策略和可解释摘要。 |
| Q056 | 如何避免记忆导致隐私风险？ | 最小化存储、用户可控、加密、访问控制、脱敏、保留期限和删除机制。 |

## Multi-Agent 与 Harness

| 编号 | 面试题 | 回答抓手 |
| --- | --- | --- |
| Q057 | 什么时候需要 multi-agent？ | 任务可分解为专业角色、并行子任务、互相审核或权限隔离时。 |
| Q058 | Multi-agent 一定比 single-agent 好吗？ | 不一定；会增加通信成本、协调复杂度、冲突和调试难度。 |
| Q059 | 常见 multi-agent 架构有哪些？ | supervisor、router、orchestrator-workers、peer collaboration、blackboard。 |
| Q060 | Agent 之间如何通信？ | 消息、共享状态、任务队列、artifact、handoff、协议如 A2A 或内部 schema。 |
| Q061 | 多 Agent 冲突如何治理？ | 明确角色权限、仲裁器、投票、优先级、证据引用、人工最终决策。 |
| Q062 | Harness 是什么？ | 把模型包装成可行动 Agent 的运行时脚手架，负责 loop、工具、状态、审批、观测和进度。 |
| Q063 | Harness 和 framework 的区别是什么？ | framework 提供构建块；harness 更像预组装运行时，默认集成循环、上下文、工具和策略。 |
| Q064 | 如何评测 multi-agent 系统？ | 子任务成功率、协作开销、冲突率、handoff 正确率、最终完成率和轨迹质量。 |

## 安全、评测与可观测

| 编号 | 面试题 | 回答抓手 |
| --- | --- | --- |
| Q065 | Prompt injection 是什么？ | 恶意内容试图覆盖系统指令、窃取数据或诱导工具越权。 |
| Q066 | RAG 场景中 prompt injection 如何出现？ | 恶意文档片段、网页内容、用户上传文件、工具返回值都可能携带指令。 |
| Q067 | 如何防御 prompt injection？ | 指令和数据分离、来源标注、权限检查、工具白名单、输出校验、人工审批。 |
| Q068 | 什么是最小权限原则？ | Agent 和工具只获得完成当前任务所需的最小数据和动作权限。 |
| Q069 | 哪些动作需要 Human-in-the-Loop？ | 付款、删除、发送外部消息、修改生产数据、权限变更、不可逆操作。 |
| Q070 | Agent eval 应该分哪些层？ | 单步、工具、检索、轨迹、最终答案、系统指标、安全指标。 |
| Q071 | 为什么只看最终答案不够？ | 中间可能越权、浪费成本、调用错误工具或泄露隐私。 |
| Q072 | Trace 应该记录什么？ | trace id、模型调用、工具调用、检索、handoff、guardrail、耗时、token、版本和错误。 |
| Q073 | 如何做失败归因？ | 按 prompt、模型能力、工具 schema、检索、上下文、权限、外部系统、业务规则分类。 |
| Q074 | LLM-as-judge 有什么风险？ | 不稳定、偏见、与生成模型同源、rubric 模糊；需要人工校准和规则补充。 |

## 生产架构、性能与成本

| 编号 | 面试题 | 回答抓手 |
| --- | --- | --- |
| Q075 | 生产级 Agent 架构通常包括哪些层？ | API、orchestrator、model gateway、tools、memory/RAG、policy、eval、trace、queue、storage。 |
| Q076 | 如何降低 Agent 延迟？ | 并行检索、模型路由、缓存、流式输出、减少轮数、异步工具、预计算。 |
| Q077 | 如何降低 token 成本？ | 上下文压缩、prompt cache、小模型路由、检索裁剪、输出预算、批处理。 |
| Q078 | 模型路由怎么设计？ | 按任务难度、风险、成本、延迟和模态选择模型，可先小模型分类再升级。 |
| Q079 | Agent 服务如何做限流？ | 用户级、租户级、工具级、模型级限流；配合队列、预算和降级策略。 |
| Q080 | Agent 如何做灰度和回滚？ | 版本化 prompt、工具、模型和检索参数；小流量实验，指标异常自动回滚。 |
| Q081 | 如何处理外部工具不稳定？ | 超时、重试、熔断、缓存、降级答案、用户告知、后台补偿任务。 |
| Q082 | 如何衡量 Agent 的生产效果？ | 任务完成率、一次解决率、人工介入率、P95 延迟、成本、错误率、用户满意度。 |

## 自测标准

每道题可以按 0 到 3 分评分：

| 分数 | 标准 |
| --- | --- |
| 0 | 只能说概念名词，无法解释机制 |
| 1 | 能定义，但缺少工程边界和例子 |
| 2 | 能讲机制、风险和权衡 |
| 3 | 能结合项目、指标、失败模式和生产方案 |

目标是在正式面试前：

- 基础题平均达到 2.5 分以上。
- 系统设计题至少 5 道能完整讲 20 分钟。
- 项目题能拿出 trace、eval、架构图和真实改进指标。
