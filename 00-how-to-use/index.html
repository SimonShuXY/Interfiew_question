00. 如何使用本手册¶

本手册不是术语清单，而是一条从 0 基础到能做 Agent 工程设计的学习路径。你应该按顺序读，因为每一章都会把前一章的概念转化成下一章的工程问题。

上一站：项目首页说明了手册目标。 本章目标：建立学习方法、学习节奏和验收标准。 下一站：正式定义 Agent，避免一开始就把所有 LLM 应用都叫 Agent。

你需要什么基础¶

0 基础可以开始，但建议逐步补齐三类能力：

能力 最低要求 为什么需要
编程 能看懂 Python 函数、JSON、HTTP API Agent 工具本质上是函数或外部 API
LLM 常识 知道模型会根据上下文生成输出 Agent 的行为来自模型、提示、上下文和工具的共同作用
工程意识 知道日志、测试、权限、错误处理的作用 Agent 会调用真实工具，风险比普通聊天更高

如果你还不会编程，也可以先阅读概念章节；到工具调用和示例代码时，再补 Python 基础。

三遍学习法¶

第一遍读概念：先搞清楚“是什么”和“为什么”。不要急着选框架。

第二遍做判断：每章都问自己：

  • 这个能力解决什么问题？
  • 如果不用它，会失败在哪里？
  • 它带来的成本、延迟和风险是什么？
  • 有没有更简单的确定性代码可以替代？

第三遍做项目：从 examples/minimal-agent 开始，再按 综合项目路线 做 3 到 5 个项目。

推荐学习顺序¶

  1. 基础篇：理解 Agent、LLM、提示词和上下文。
  2. 核心篇：学习工具、RAG、记忆、Agent 循环和规划。
  3. 架构篇：比较工作流、单 Agent、多 Agent、MCP、A2A。
  4. 工程篇：补齐评测、观测、安全、生产化。
  5. 精通篇：选择框架，做综合项目，形成自己的技术判断。

每章怎么读¶

每章都按这个结构组织：

  • 连接：说明本章与前后章节的关系。
  • 核心概念：解释必须掌握的知识。
  • 工程判断：说明什么时候用，什么时候不用。
  • 常见误区：避免把 Agent 做复杂却不可控。
  • 练习：把知识变成可验证的能力。

学习验收标准¶

当你能完成下面这些任务时，说明你不是只记住了名词：

  • 给一个业务需求，判断它适合函数、工作流、RAG、单 Agent 还是多 Agent。
  • 写出一个 Agent 的工具清单，并解释每个工具的输入、输出、权限和失败策略。
  • 为 Agent 设计至少 20 条评测样例，覆盖正常、边界、恶意和失败路径。
  • 画出生产架构：用户入口、Agent runtime、工具服务、数据层、日志追踪、权限和人工审核。
  • 解释为什么某个框架适合或不适合你的场景。
