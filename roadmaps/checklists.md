# Agent 工程检查清单

这些清单用于项目设计、代码审查和上线前自检。

## 需求判断

- [ ] 任务是否真的需要 Agent？
- [ ] 是否能用普通函数或固定工作流解决？
- [ ] 成功标准是否可定义？
- [ ] 是否有明确失败策略？
- [ ] 是否有高风险动作？
- [ ] 是否需要人工介入？

## 上下文

- [ ] 系统规则是否清晰？
- [ ] 业务规则是否集中维护？
- [ ] 外部资料是否标记为不可信上下文？
- [ ] 是否避免把无关长文本塞进 prompt？
- [ ] 输出是否有结构化 schema？
- [ ] 状态摘要是否服务下一步决策？

## 工具

- [ ] 工具名称是否具体？
- [ ] 参数 schema 是否严格？
- [ ] 返回值是否结构化？
- [ ] 错误是否可恢复？
- [ ] 权限是否最小？
- [ ] 动作工具是否幂等？
- [ ] 高风险动作是否审批？
- [ ] 是否记录 trace 和审计日志？

## RAG 和记忆

- [ ] 文档切分是否符合业务语义？
- [ ] metadata 是否包含来源、时间、权限？
- [ ] 检索结果是否有引用？
- [ ] 资料不存在时是否拒绝编造？
- [ ] 用户记忆是否获得同意？
- [ ] 记忆是否可删除、可过期？

## Agent loop

- [ ] 是否有最大轮数？
- [ ] 是否有时间和成本预算？
- [ ] 是否检测重复工具调用？
- [ ] 工具连续失败时是否停止？
- [ ] 缺信息时是否询问用户？
- [ ] 是否保存可恢复 checkpoint？

## 多 Agent

- [ ] 是否真的需要多 Agent？
- [ ] 每个 Agent 职责是否互斥？
- [ ] 工具和权限是否隔离？
- [ ] handoff 条件是否明确？
- [ ] 是否避免共享完整历史？
- [ ] 是否有结构化交接 schema？

## 评测

- [ ] 是否有离线评测集？
- [ ] 是否覆盖正常、边界、恶意、失败路径？
- [ ] 是否评测工具调用轨迹？
- [ ] 是否评测禁止行为？
- [ ] 是否记录模型、prompt、工具版本？
- [ ] CI 是否跑关键回归？

## 上线

- [ ] 日志是否脱敏？
- [ ] trace 是否可查询？
- [ ] 是否有限流？
- [ ] 是否有降级策略？
- [ ] 是否有人工接管流程？
- [ ] 是否有成本报警？
- [ ] 是否有 runbook？
- [ ] 是否明确已知限制？
